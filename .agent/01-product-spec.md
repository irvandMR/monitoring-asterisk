# PBX Dashboard — Product Specification

## 1. Call to Dial

Purpose:
Allow an operator/admin to configure and monitor click-to-call infrastructure.

### Overview
Show:
- Registered trunks
- Active extensions
- Calls today
- Recent call activity

### Trunk & Endpoint
Trunk fields should support the actual PBX integration requirements, including:
- Name
- Vendor
- Transport
- Host/address
- Port
- Registration/authentication settings where applicable
- Codec configuration
- Context
- Status
- Qualification/availability

Extension fields should support:
- Extension number
- Display/name
- Transport
- WebRTC flag
- AOR
- Authentication
- Context
- Contact status
- Enabled/disabled state

### Routing
Support:
- Outbound rules
- Inbound rules
- Fallback routes
- Caller ID behavior
- Source/extension matching
- Destination/trunk mapping
- Rule priority

### Advanced
Show a generated/read-only configuration preview.

The preview is informational. The source of truth should be the configured backend/database when realtime mode is enabled.

## 2. DeskCall Koor

Purpose:
Internal desk-to-desk calling and coordination.

The reference prototype describes:
- Ring groups
- Extension groups
- Escalation rules when a call is unanswered

Design the module so these can be configured independently from Call to Dial.

## 3. Predictive

Purpose:
Configure and monitor predictive dialer campaigns.

The reference prototype mentions:
- Active campaigns
- Pacing ratio
- Trunk capacity per campaign
- Agent pools receiving dial results

Do not invent additional business rules without backend requirements.

## 4. Call Center

This module is planned and should not be implemented as a complete feature unless explicitly requested.

The prototype identifies future concepts:
- Queue
- Agent
- IVR
- SLA

For now it can remain a disabled/planned navigation item.

## Configuration source

Support two conceptual modes:
1. Realtime DB
   - Database is the configuration source.
   - UI changes persist immediately through API.
   - PBX configuration is synchronized/generated by the backend.

2. Static `.conf`
   - Configuration is file-based.
   - UI should clearly indicate that changes require manual reload/reload workflow.

Never silently mix the two sources.
